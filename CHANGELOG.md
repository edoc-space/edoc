# История версий

## 1.4.0 — 2026-11-18

- Единый контракт тем builtin/local/package, выбор темы и переопределение оболочек без копирования движка.
- Отключаемый блог Markdown/MDX: черновики, публикация по дате, теги, годовой архив, пагинация и RSS 2.0 по локалям.
- Закрытые графы статей и preview с проверками публикации, локали, входов и сборки на GET/HEAD; скрытые материалы не попадают в публичную выборку.
- Общие Card/Grid/Filters, ссылки на всю карточку, последние статьи и каталог блоков; импорт React-компонентов сайта и установленных пакетов из MDX.
- Уточнены доступность диалогов, вкладки, документация и media; добавлены RU/EN руководства и реальные снимки стандартной темы.

Версия фиксируется Git-тегом. После обновления требуется production-сборка выбранного сайта; темы и контент хранятся отдельно в `local/`. Релиз не выполняет развёртывание сайта. Прежнее отсутствие обновления head/canonical при SPA-переходе остаётся известным ограничением; исходный HTML и reload проверены.

## 1.3.1 — 2026-10-15

- ReactSoftBox обновлён с 2.4.3 до 2.8.2; минимальная версия UI-пакета
  в `package.json` — `^2.8.2`, обновлён `yarn.lock`.

  транзитивные зависимости в `composer.lock`.

  объявлен прямой зависимостью приложения.

  преобразуются в `CookieSecurePolicy` без ошибки типа. Добавлены проверки
  политик `always`/`never`/`auto` и значений `0/1` для HTTP и HTTPS.
- PostCSS обновлён с 8.5.15 до 8.5.28 в `yarn.lock`: устранено чтение
  внешних `.map` через `sourceMappingURL`, включая вызовы без `from` и
  обход через символические ссылки. Обновлена его зависимость `nanoid`.

## 1.3.0 — 2026-09-29

### Требования и совместимость

- Минимальная версия PHP повышена с 8.4 до 8.5.
- Зависимости `phpsoftbox/*` переведены с `dev-master` на стабильную ветку
  `^1`; обновлён `composer.lock`, удалён `minimum-stability: dev`.
- `phpsoftbox/cs-fixer` требует `^1.2.2`.
- Загрузка конфигурации использует обязательный `ConfigFactory::baseDir`
  и аргумент `environment`. CLI получает окружение приложения.
- Канонические ссылки учитывают `X-Forwarded-*` только от доверенных прокси.
  Настройка `APP_TRUSTED_PROXIES` применяется через `TrustedProxyMiddleware`
  в начале обработки запроса.

### Переход с 1.x

1. Подготовьте PHP 8.5, установите зависимости по `composer.lock` и соберите
   фронтенд. Пользовательский контент и плагины остаются в `local/`.
2. Для работы за обратным прокси задайте `APP_TRUSTED_PROXIES` фактическими
   IP/CIDR. Не используйте весь Интернет как доверенный диапазон.
   В Nginx передавайте исходные `HTTPS` и `REQUEST_SCHEME`; уберите прежние
   `map`, которые подменяли их по `X-Forwarded-Proto` до проверки доверия.
3. Очистите прежние кеши окружения, конфигурации, маршрутов и
   скомпилированного контейнера, затем перезапустите PHP-процессы.
   Для DI доступен `ContainerBuilder::clearCompiledCache()` с каталогом
   `Path::cachePath('di')`. Контент и плагины при очистке кешей не затрагиваются.
4. Если установка использует шифрование, новые операции требуют ключа
   не короче 32 байт. Не заменяйте рабочий ключ без сохранения возможности
   прочитать прежние данные. Старые зашифрованные cookie требуют повторного входа.
